# Architecture Decision Records

Significant architectural decisions are recorded in this directory.

## Naming

```text
0001-use-modular-monolith.md
0002-source-snapshots-as-evidence.md
0003-async-provider-execution.md
```

## Required sections

Each ADR should include:

- Status
- Date
- Context
- Decision
- Alternatives considered
- Consequences

## Lifecycle

Suggested statuses:

- `PROPOSED`
- `ACCEPTED`
- `SUPERSEDED`
- `REJECTED`

When an ADR is replaced, do not delete it. Mark it `SUPERSEDED` and link to the replacement.
